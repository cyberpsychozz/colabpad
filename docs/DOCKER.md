# CollabPad в Docker

Docker добавлен по запросу владельца 9 ноября 2026 года. Один контейнер приложения
содержит Python-сервер и собранный интерфейс. SQLite хранится в отдельном именованном
томе. В контейнере остаётся один worker Uvicorn.

## Запуск

Нужны Docker Engine и Docker Compose. Из корня проекта:

~~~bash
docker compose up --build -d --wait
~~~

Открой http://127.0.0.1:1744. Состояние и логи:

~~~bash
docker compose ps
docker compose logs --tail=100 app
~~~

Перезапуск и остановка:

~~~bash
docker compose restart app
docker compose down
~~~

Эти операции сохраняют том collabpad_data. Переименование проекта Compose создаёт
другой том. Существующая база из локальной папки data/ автоматически не переносится;
инструкция переноса приведена ниже.

Если порт 1744 занят, используй другой порт с соответствующим CORS_ORIGINS:

~~~bash
COLLABPAD_PORT=8080 CORS_ORIGINS=http://localhost:8080,http://127.0.0.1:8080 docker compose up --build -d --wait
~~~

Эти значения нужно использовать и в последующих командах Compose; для постоянной
настройки запиши их в .env.

## Устройство сборки и настройки

Dockerfile собирает интерфейс в стадии Node.js, выполняя клиентские тесты.
Зависимости Python устанавливаются в отдельной стадии. Итоговый образ содержит
Python, приложение, собранный интерфейс и утилиту резервного копирования.
Node.js и исходники фронтенда в итоговый образ не переносятся.

Compose берёт настройки приложения из переменных окружения или локального .env;
допустимые значения соответствуют .env.example. Папка данных внутри контейнера
фиксирована: /var/lib/collabpad (DATA_DIR). В ней лежат база collabpad.db и папка
sprites/ со спрайтами оживлённых рисунков, обе в одном томе. Игровые настройки и
флаги (config/*.yaml) копируются в образ при сборке. Симуляция мира работает
отдельным процессом внутри этого же контейнера; второй контейнер не нужен. COLLABPAD_PORT задаёт порт компьютера
(по умолчанию 1744), внутри контейнера всегда используется 8000.

Процесс работает от пользователя с UID/GID 10001. Корневая файловая система
контейнера доступна только для чтения; запись разрешена в том SQLite и временную
папку. Порт компьютера опубликован на 127.0.0.1.

.dockerignore допускает только исходники, необходимые сборке. Локальная база,
резервные копии, .env, Git, .venv, node_modules и прежняя сборка в образ не попадают.
Healthcheck проверяет /api/health средствами стандартной библиотеки Python.

## Обновление

После получения новых исходников:

~~~bash
docker compose up --build -d --wait
~~~

Приложение пересоздаётся с прежним томом базы. Клиенты переподключаются автоматически.
Делать больше одной реплики приложения нельзя: комнаты, аренда управления и
симуляция мира находятся в памяти одного процесса.

## Резервные копии

Для создания проверенной копии работающей базы:

~~~bash
docker compose exec app python deploy/backup.py
docker compose cp app:/var/lib/collabpad/backups ./backups
~~~

Утилита использует SQLite Backup API, проверяет целостность и хранит 14 последних
дневных копий в томе. Рядом, в backups/sprites/, она держит зеркало папки спрайтов. Папка backups/ на компьютере исключена из Git.
Для автоматизации первую команду (с `exec -T`) запускают ежедневным cron на сервере,
см. docs/agent/deploy.md.

## Перенос базы из запуска без Docker

1. Останови локальный сервер и Docker-приложение. Создай онлайн-копию исходной базы:

~~~bash
python3 deploy/backup.py --db data/collabpad.db --directory backups
~~~

2. Импортируй полученный файл в новый, ещё пустой том. Замени YYYY-MM-DD датой
из имени файла, которое напечатала предыдущая команда:

Если Docker-версия уже запускалась, используй отдельный проект для переноса:
добавь -p collabpad-migrated сразу после docker compose во всех дальнейших
командах. Он получит новый том; последующие запуск, остановка и обновление
должны использовать то же имя проекта.

~~~bash
docker compose run --rm --no-deps -T app python -c 'import shutil,sys; from pathlib import Path; target=Path("/var/lib/collabpad/collabpad.db"); stream=target.open("xb"); shutil.copyfileobj(sys.stdin.buffer,stream); stream.close()' < backups/collabpad-YYYY-MM-DD.db
~~~

Команда создаёт файл от пользователя приложения и отказывается перезаписывать
существующую базу. Используй только копию, успешно созданную deploy/backup.py.
Исходная база в data/ остаётся на компьютере.

3. Запусти приложение:

~~~bash
docker compose up -d --wait
~~~

## VPS и внешний Nginx

Сервер работает так же: Compose для приложения и Nginx хоста перед ним, на
127.0.0.1:1744. Пошаговая установка, обновление, бэкапы и удаление —
в docs/agent/deploy.md (на английском).
