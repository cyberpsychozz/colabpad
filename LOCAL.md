# Локальный ColabPad

Это готовая локальная реализация MVP из AGENTS.md. ТЗ сохранено, README и AGENTS.md дополнены инструкциями Docker по новому запросу владельца. Для быстрого запуска используй этот файл.

## Запустить сейчас

Через Docker:

~~~bash
docker compose up --build -d --wait
~~~

Открой http://127.0.0.1:8000. Остановка — docker compose down. Python и Node.js
на компьютере для этого способа не нужны. База Docker хранится в отдельном томе;
перенос базы из data/ выполняется отдельно по [инструкции](docs/DOCKER.md).

### Запуск без Docker

Окружение и фронтенд уже подготовлены в этой папке:

~~~bash
./start.sh
~~~

Открой http://127.0.0.1:8000. Остановка — Ctrl+C. Документация API: http://127.0.0.1:8000/docs.

Скрипт слушает только локальный адрес. База находится в data/colabpad.db и переживает перезапуск и пересборку. Удалять её нельзя, если нужны рисунки.

## Установка с чистого клона

Нужны Python 3.12 и Node.js 20.19+. На Ubuntu при необходимости установи python3.12-venv.

~~~bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cd web
npm ci
npm run build
cd ..
./start.sh
~~~

Если ensurepip отсутствует, но системный pip доступен:

~~~bash
python3.12 -m venv --without-pip .venv
python3.12 -m pip --python .venv install -r requirements.txt
~~~

Для разработки запусти отдельно:

~~~bash
env -u PYTHONPATH .venv/bin/python -m uvicorn app.main:asgi --reload --port 8000 --no-access-log
~~~

И во втором терминале:

~~~bash
cd web
npm run dev
~~~

Открой http://localhost:5173. Для запуска собранной версии и для Vite в .env.example перечислены локальные origin. Если меняешь PORT или адрес Vite, поправь CORS_ORIGINS. В production указывай только https://collabpad.ru.

## Проверки

~~~bash
env -u PYTHONPATH .venv/bin/python -m pytest -q
cd web
npm test
npm run build
~~~

Клиентские тесты используют встроенный тестовый модуль Node.js; дополнительных библиотек для тестирования нет. Ruff используется только как внешний инструмент форматирования.

Для ручной проверки создай холст, открой его ссылку в двух вкладках, рисуй в обеих. Останови сервер на 30 секунд, продолжай рисовать в открытой вкладке, запусти сервер: очередь должна сохраниться. Затем обнови страницу, проверь таймлапс, PNG и Pro.

Очередь хранится в памяти вкладки. Перед её закрытием с несохранёнными штрихами браузер предупреждает; после закрытия вкладки восстановить такую очередь нельзя.

## Что подготовлено для VPS

В deploy/ находятся Nginx, первоначальная HTTP-конфигурация для certbot, systemd, таймер ежедневной онлайн-копии SQLite с хранением 14 копий, скрипт обновления и хук продления сертификата. Порядок установки — в исходном README.md. После установки сервиса бэкап включается так:

~~~bash
sudo install -m 644 deploy/systemd/colabpad-backup.service /etc/systemd/system/
sudo install -m 644 deploy/systemd/colabpad-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now colabpad-backup.timer
sudo install -m 755 deploy/renew-hook.sh /etc/letsencrypt/renewal-hooks/deploy/colabpad
~~~

Создай /var/lib/colabpad/backups с владельцем colabpad. Копирование живого файла базы через cp не применяется: deploy/backup.py использует SQLite Backup API и проверяет целостность результата.

Логи HTTP-доступа и Nginx с адресами посетителей отключены согласно требованию не сохранять IP. Для ошибок приложения остаются сообщения с traceback без содержимого штрихов и запросов. В Uvicorn всегда один worker.

Публикация, настройка DNS, сертификаты и внешний тест с друзьями не выполнялись: текущая задача ограничена локальной работой.

## Принятые решения по документам

1. В DOCX проверка лимита предшествует дедупликации. Следуем более свежему AGENTS.md: сначала ищем clientId, затем проверяем лимит. Это сохраняет безопасную повторную отправку на заполненный холст.
2. В DOCX другое сообщение о медленной загрузке. Использовано сообщение из AGENTS.md.
3. Раздел 8 AGENTS.md требует получать настройки клиента с сервера, а сокращённый список полей в разделе 6.2 перечисляет не все настройки. В ответ загрузки включены maxPointsPerStroke, maxPayloadBytes, simplifyEpsilon и nameMaxLen; обязательные поля и события сохранены.
4. Для восстановления используется максимальный наблюдаемый seq и дополнительно непрерывный подтверждённый префикс. Если событие с большим seq пришло раньше пропущенного, догрузка начинается с префикса, чтобы не оставить пробел.

Текущий статус выполнения и границы проверки — в docs/STATUS.md.
